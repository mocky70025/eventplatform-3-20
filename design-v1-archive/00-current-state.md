# PHASE 1a 現状把握サマリー

教科書プロセス（orotyan-design-process）の起点として、既存資料・コードから現状を整理。

## プロダクト概要

- **サービス名**: Wacca（ワッカ）
- **コンセプト**: 「輪（わ）」= 主催者と出店者が出会い、つながる「輪」をつくるプラットフォーム
- **形態**: マッチングプラットフォーム
  - **主催者**: イベント（祭り・マルシェ等）を企画し、出店者を募集する側
  - **出店者**: キッチンカー・屋台などで出店申請する側
- **状態**: ローンチ前、実ユーザー0人

## システム構成

| アプリ | 対象 | URL | 色 |
|---|---|---|---|
| **organizer** | 主催者 | localhost:3002 | Orange (#f97316) |
| **store** | 出店者 | localhost:3001 | Green (#10b981) |
| **admin** | 運営者 | localhost:3000 | Blue（今回スコープ外） |

技術スタック: Next.js 16 (App Router) + React 19 + TypeScript / Tailwind v4 / Supabase / LINE Login / Noto Sans JP

## 現状の画面マップ

### organizer（17画面）
ダッシュボード、イベント作成、イベント編集、イベント一覧、イベント詳細、出店者管理、申請レビュー、出店者詳細、通知、プロフィール、オンボーディング、ログイン/サインアップ、利用規約

主な動線：
```
ログイン → ダッシュボード → イベント作成
                          → 出店者管理 → 申請レビュー → 承認/却下
```

### store（16画面）
ホーム、イベント検索、イベント詳細、出展申請フォーム、申請一覧、申請詳細、プロフィール（基本情報/書類/写真/レビュー/通知）、通知、オンボーディング、ログイン/サインアップ、イベント履歴、主催者詳細、利用規約

主な動線：
```
ログイン → ホーム → イベント検索 → イベント詳細 → 出展申請フォーム
                                                  → 申請状況確認 → 履歴
```

特徴：書類アップロード（営業許可証等）に OpenAI API（GPT-4o mini）で自動読み取り機能あり。

## 既存デザイン方針（DESIGN.md ルート）

- **トーン**: カジュアル、温かみ、親しみやすい
- **参考**: Cookpad — 家庭的で温かみのあるUGCプラットフォーム
- **タイポ**: Noto Sans JP（300/500/600/700）
- **角丸**: 12px（rounded-xl）
- **影**: ソフト（opacity 0.06〜0.08）
- **NG**: emoji禁止、純黒禁止、強い影禁止、organizer/store間でレイアウト構造を変えない

## 次のフェーズで明らかにすべきこと

1. **競合・代替手段**: 現状ユーザーは何を使っているか（PHASE 1b）
2. **想定ターゲット**: 具体的に誰が使うのか（PHASE 1c → PHASE 2 ペルソナ）
3. **解くべき課題**: 既存代替の何が不足しているか（PHASE 1b/c → PHASE 2 CJM）

## 注意点

- 既存のブランドストーリー（「輪」「賑わいと信頼の両立」）と既存のテイスト（Cookpad風、温かみ）は**ユーザーが意図して決めた強い前提**である可能性が高い。
- このプロセスで「実はもっとビジネス向けに振るべき」等の反転発見があれば指摘するが、基本は既存方針を尊重して具体化する。
